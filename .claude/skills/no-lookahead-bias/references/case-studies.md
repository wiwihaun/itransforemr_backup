## 1. 測試集百分位門檻

**症狀**　回測要取「機率最高的前 20%」當進場訊號，寫成：

```python
th = np.percentile(prob, 80)      # prob 是整個測試期的預測機率
signals = index[prob >= th]
```

**為什麼是洩漏**　實時交易在第 k 根 K 棒時，只知道 1..k 的機率，不可能知道未來 2,800 根的分佈長怎樣。這個門檻用到了整段測試期的資訊。

**修正**　門檻必須在訓練結束時就從驗證集固定下來：

```python
# calibrate.py：訓練完成後輸出各百分位門檻
thresholds = {str(p): float(np.percentile(val_prob, 100 - p)) for p in PCTS}
json.dump({'val_thresholds': thresholds, ...}, f)

# 回測：直接讀取，絕不重算
VAL_TH = json.load(open('calibration.json'))['val_thresholds']
assert VAL_TH, '缺少 val_thresholds，請先重跑校準'
th = VAL_TH['20']
```

**影響**　這次運氣好，驗證集的 80 百分位是 0.2706、測試集是 0.2694，只差 0.0013。持倉佔用制的報酬從 +23.86% 變成 +20.97%（差 3pp）。**但事前無法知道影響會這麼小**——分佈偏移大的時候可以差很多。

**教訓**　「影響很小」是事後才知道的，不能當作不修的理由。

## 2. 標籤尾端未剔除

**症狀**　標籤定義是「未來 168 根內先觸及 +6% 還是 −2%」。最後 168 筆沒有足夠的未來 K 棒，函式回傳預設值 0。

**為什麼是洩漏**　嚴格說是「標籤損毀」而非洩漏，但後果一樣嚴重：時間序列的測試集就在尾端，這 168 筆全部落在測試集裡。測試集有 666 筆時，這是 **25%** 的樣本被系統性標成 0。

**修正**

```python
df['target'] = target_long(df, lookahead=168, tp_pct=0.06, sl_pct=0.02)
df = df.iloc[:-168].reset_index(drop=True)   # 未來資料不完整的尾巴
```

**一般化**　任何 `lookahead=N` 的標籤，都必須砍掉最後 N 筆。順帶要多下載 N 筆資料，否則會犧牲掉你真正想分析的區間末端。

## 3. 在雜訊上做特徵篩選

**症狀**　用 GBDT 的 permutation importance 篩特徵，30 個砍到 14 個。

**為什麼是洩漏**　當模型本身沒有預測力（測試 AUC 0.4955，低於隨機）時，permutation importance 全部是雜訊——最大值只有 +0.0084，且半數為負。照著它篩選等於在挑雜訊。

**影響**　精簡後測試 AUC 從 0.4955 掉到 **0.4231**，比原本更差。

**修正順序**　先查出真正的原因（這個案例是非平穩特徵造成的分佈偏移，見案例 7），修好之後再篩：31 個特徵砍到 11 個，AUC 從 0.4824 提升到 0.5257，bootstrap 95% CI [0.5028, 0.5506]。

**教訓**　**AUC ≈ 0.5 時不要做特徵選擇。** 先確認有訊號可篩，再篩。而且重要度一律在驗證集上算，不能用訓練集（過擬合的假重要度）也不能用測試集（決策洩漏）。

## 4. 校準器記憶驗證集

**症狀**　比較四種機率校準器，用驗證集 Brier score 選最佳：

```
方法          val Brier   val ECE   test Brier  test ECE  test AUC
未校準          0.24889   0.25401      0.25032   0.21718   0.5425
Temperature    0.24883   0.25645      0.25007   0.21680   0.5425
Platt          0.18395   0.02437      0.20457   0.04369   0.5425
Isotonic       0.17919   0.00000  ←    0.20766   0.06069   0.5045  ← AUC 崩了
```

**為什麼是洩漏**　Isotonic 的 val ECE 是 **0.00000**——完美到不合理，那是它把驗證集的分箱記下來的產物。直接比 val Brier 就會選到它，而它在測試集把 2,805 筆壓成 2 個分箱、AUC 從 0.5425 崩到 0.5045。

**修正**　用驗證集內的 5-fold CV 取得 out-of-fold 分數，再套 **one-standard-error rule**：

```python
# CV 分數在最佳者的 1 個標準誤內視為打平，此時選較簡單的模型
raw_best = min(pool, key=lambda k: cv[k])
thresh = cv[raw_best] + cv_se[raw_best]
within = [k for k in pool if cv[k] <= thresh]
best = min(within, key=lambda k: COMPLEXITY[k])
```

結果：Platt (0.18422) 與 Isotonic (0.18161) 落在同一個 1-SE 區間，Platt 只有 2 個參數且保證單調平滑，因此勝出。測試集 ECE 0.21718 → 0.04369。

**這個案例最值得注意的地方**　我為了選校準器連續換了三種規則（val Brier → CV Brier → AUC 守門），三種給出三種答案。**「換規則直到得到想要的答案」本身就是 p-hacking**。正確做法是採用一個有文獻依據、事前就能說明理由的規則，然後接受它的答案。

## 5. 多重比較汙染

**症狀**　在同一個測試集上比較了 4 種進場規則 × 3 個門檻 = 12 種組合，選出最好的那個，得到 p = 0.062。

**為什麼是洩漏**　即使真實效果為零，比較 12 種設定時最小 p 值的期望值大約是 1/(12+1) ≈ **0.077**。所以 p=0.062 完全落在「純運氣」的範圍內，不構成任何證據。

**還有一個陷阱**　我後來掃了 9 個門檻，全部為正、0 次翻轉，看起來很有說服力。但那 9 個門檻是**嵌套子集**（前 1% 包含在前 2% 裡），彼此高度相關，證據力遠小於 9 次獨立檢定。

**修正**　沒有事後補救的辦法。只能：
1. 事前宣告要用哪個設定
2. 或保留一份從未動過的最終測試集
3. 或照實報告並據此打折看待

**可以直接用的報告句型**

> 這些數字是在同一個測試集上比較了 12 種設定之後才選定的，這個選擇本身就用掉了測試集的資訊，所以不能當作已驗證的預期表現。比較可信的是最大回撤的改善（−21.6% → −11.5%）——那是結構性後果（不再反覆撞同一個市場狀態），且在三個門檻上都成立，不是用報酬率挑出來的。

## 6. 事後挑最佳操作點

**症狀**

```python
MAIN = best_p     # best_p = max(sweep, key=lambda p: sweep[p]['ret'])
```

報告的「主要操作點」直接取表現最好的那個門檻。

**為什麼是洩漏**　這是 L4 的教科書案例。程式碼沒有錯，但「最好的門檻」是看過測試集結果才知道的。

**修正**

```python
# 事前宣告，不挑最好看的
MAIN = 20
th = VAL_TH[str(MAIN)]
...
print(f'事後最佳門檻是前 {best_p}%（{sweep[best_p]["ret"]*100:+.2f}%）'
      f'——僅供參考，主要操作點不採用')
```

事後最佳值還是可以印出來當診斷，但要明確標示「不採用」。

## 7. 非平穩特徵的分佈偏移

**症狀**　把資料從 1.6 年拉長到 6.5 年後，模型表現不升反降。查訓練集與測試集的特徵範圍：

| 特徵 | 訓練集範圍 | 測試集範圍 | 測試值出界比例 |
|---|---|---|---|
| EMA_95 | [−1.49, 2.10] | [1.67, 4.96] | **88.3%** |
| EMA_72 | [−1.50, 2.11] | [1.62, 4.99] | 86.5% |
| Close | [−1.59, 2.30] | [1.45, 5.24] | 79.1% |

**為什麼相關**　嚴格說這不是洩漏（沒有偷看未來），但它破壞的是同一個東西——**訓練集與測試集的契約**。BTC 從 $7,000 漲到 $70,000，用訓練集前 70% 的均值標準差做 z-score 後，測試期幾乎整段落在訓練分佈之外。樹模型無法對沒見過的數值切分，Transformer 等於吃到極端 OOD 輸入。

**修正**　把價格單位的量轉成比例：

```python
df['Close_vs_EMA72'] = close / df['EMA_72'] - 1     # 取代 Close 與 EMA_72
df['MACD_pct']       = df['MACD'] / close           # 取代 MACD
df['ATR_14_pct']     = df['ATR_14'] / close         # 取代 ATR
df['OBV_z'] = (df['OBV'] - df['OBV'].rolling(200).mean()) / df['OBV'].rolling(200).std()
df['Volume_rel'] = df['Volume'] / df['Volume'].rolling(200).mean()
```

平均出界比例 8.65% → **0.03%**，最大 88.3% → 0.2%。

**查法**（值得寫成常規檢查）

```python
for c in feature_cols:
    a, b = df[c].values[train_slice], df[c].values[test_slice]
    out_of_range = ((b < a.min()) | (b > a.max())).mean()
    if out_of_range > 0.10:
        print(f'⚠ {c}: {out_of_range*100:.1f}% 的測試值超出訓練集範圍')
```

## 8. 反例：叢集判定其實是 causal

**症狀**　進場規則是「每個訊號叢集只取第一根」。直覺上很可疑——要知道這是叢集的第一根，不是得先看到整個叢集嗎？

**驗證**　寫一個嚴格串流的版本，逐根推進、只能讀當下與過去，跟向量化版本逐筆比對：

```python
def stream_entry(th, gap=6):
    out, busy, last_sig = [], -1, None
    for j in range(len(prob)):
        k = index[j]
        if prob[j] < th:
            continue
        is_new = (last_sig is None) or (k - last_sig > gap)
        last_sig = k                    # 不論有沒有進場都要更新
        if not is_new or k <= busy:
            continue
        ex, ret, why = simulate(k)
        out.append((k, ex, ret, why)); busy = ex
    return out

assert stream_entry(th) == vectorized_cluster_first(index[prob >= th])
```

結果：**逐筆完全相同，33 筆。** 因為「叢集第一根」的定義是「前 6 根內沒有訊號」——純粹回看。

真正的洩漏在同一份程式碼的另一個地方：門檻用了測試集百分位（案例 1）。

**教訓**　可疑的地方要驗證，不要憑感覺改。憑感覺改會同時做錯兩件事——改掉沒問題的、放過有問題的。串流等價測試只要寫一次，之後留在程式裡當迴歸測試，幾乎不花時間。

**注意這個實作細節**　`last_sig = k` 必須對每個訊號都執行，即使那個訊號因為持倉中而被跳過。漏掉這行，狀態機的行為就會跟實時不同——這種 bug 靜態掃描抓不到，只有串流測試會爆。
